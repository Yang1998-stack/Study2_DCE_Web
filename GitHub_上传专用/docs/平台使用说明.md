# Study 2燕麦饮DCE平台：1 L三价格候选设计

本项目在原平台内升级，保留原始数据库、4个广告条件、独立的信息核验/质量报告属性、研究者后台、进度恢复、数据导入导出、详情查看过程记录及QuickForm同步。

**当前为新设计的演示/预测试候选版本，尚未获得用户确认及完成预测试，formal收数和正式QuickForm发送均已硬锁。** 不会因设置旧环境变量就开启正式收集。

## 2. Windows启动

核心服务需要Python 3.10及以上，只用标准库。XLSX导入可选安装config/requirements-optional.txt。只运行已生成的实验，不需要NumPy/SciPy。

1. 初次使用研究者后台，双击“管理工具/设置_研究者账号.bat”，设置账号与至少12字符密码；已有服务需先停止。
2. 双击“一键启动_本地演示.bat”，保持命令窗口打开。
3. 浏览器打开[实验页面](http://127.0.0.1:8000)，后台为[/admin](http://127.0.0.1:8000/admin)。

也可在项目目录运行：

```powershell
python server.py admin-setup
python server.py
```

demo不上传QuickForm；“重新体验实验”创建新demo编号，不覆盖既有记录。demo后台可指定广告组与区组，普通受访者不能指定。预测试使用“管理工具/启动_预测试.bat”或：

```powershell
$env:DCE_MODE='pilot'
python server.py
```

如果配置私有quickform.env.cmd，先从管理工具/quickform.env.example.cmd复制到项目根目录并自行填写。不要把私有配置、密码、邀请码及数据目录公开。切换DCE_DATA_DIR后需在相应数据目录配置后台账号。

## 3. 消费者流程与条件控制

知情同意 → 商品浏览 → 所有组一致的属性说明 → 8道购买任务 → 原有后续问卷 → 统一研究说明。

购买情境：“请设想您正在电商平台为家庭日常饮用选购原味燕麦饮。您刚才浏览了一则1 L燕麦饮广告，接下来将比较几组同规格的假设性商品。请结合商品资料、个人需求及日常预算，选择您最愿意购买的一款，也可以选择暂时不购买。”

广告保持原文件：G1/G3共用chart.jpg，G2/G4共用nature.jpg。只有G3/G4显示原有英文AI来源披露。无披露组不暗示真实摄影。广告完整显示，包装与购买任务统一为1 L。原素材不编辑。

在本实例、模式及设计版本内，对4广告组×2区组的最少人数单元随机分配；区组内题序随机，每题独立50%交换A/B显示位置，保留原始题号、属性组合、显示顺序及交换位。基础题库A/B边际平衡不等于每名受访者恰好4次交换。

所有商品基础配方、口味、营养资料及食品安全假设相同；价格改变不会增加有机认证、质量等级或营养优势。环境与质量信息两属性分别读取0/1，不绑定。

“查看环境信息”和“查看食品质量资料”使用同样式面板。两个水平的基础资料相同；水平1仅增加对应记录模块。模拟资料均明确标识，不使用真实机构Logo或外部认证，不伪造实测结果。商品、批次及模拟记录编号均适配1 L液体燕麦饮。

服务器记录详情是否确认展示及前台可见时长，切到后台暂停；断网关闭后按事件编号补传，重复上报不重复计时。选择后必须点击确认才保存，未选不能提交；已提交题目不能覆盖，网络重试幂等。刷新或服务重启后同一Cookie可恢复新版已提交进度。Cookie丢失不能仅凭可猜测的参与编号取回答卷。

查看行为是额外过程变量，不能直接解释为核验的因果效应。旧未采集时间及查看行为留空，不推算。后台有效样本仍须研究者按事先规则人工审核，完成不自动有效。

## 4. 历史数据与版本隔离

旧designs/tasks_legacy_v1.json及designs/legacy_v1_config.json保留原版题目与哈希，旧版编号study2-16-v1。旧答卷、选择、随机分配、时间及QuickForm快照不覆盖、不转换成新价格或新容量。旧说明已清理；旧版任务与原始答卷继续保留。

后台增加“设计版本”选择器：当前版与历史版分别统计、导出、校验导入。同一文件中的版本/题目哈希不一致会拒绝导入。默认导出仅包含当前版。旧价与旧规格在历史版本导出中仍必须如实保留；它们不是新版残留，不允许为清理而改写。

旧Cookie进入时显示历史会话已保存，不拿新版界面继续旧题。demo可重新体验建立新的新版会话；其他模式的旧会话请研究者处理。旧进度原样留存，不会自动成为新版样本。

命令行明确导出旧版：

```powershell
$env:DCE_MODE='demo'
python server.py export --design-version study2-16-v1
```

数据库designs表保留两个版本快照；新增加的choice_products表逐题逐显示商品保存原料、两项信息编码、price_yuan、price_level、product_volume_ml及design_version，文案另存choice_display_snapshots。不把属性从当前新版套回旧数据。

## 5. 后台、导入与导出

登录/admin，按模式和设计版本查看已开始、已完成、未完成、人工审核有效人数、各广告组完成率、区组人数、逐题A/B/N次数、每人进度与时间。已开始指完成同意并建立会话，单纯访问不算样本。时间包含中途暂停，不能当作纯阅读时间。

导入：选择与来源相同模式和版本 → 上传participants.csv及choices.csv/choice_long.csv → 可附detail_views.csv → 预览字段、记录数、错误与重复提示 → 明确确认后一次事务写入。单文件8 MiB、总请求12 MiB、每表20000行/100字段；XLSX需安装可选openpyxl。原文件及日志私下保存，不补造选择。跨实例按来源实例+原编号+模式命名；相同来源身份一致则跳过，冲突拒绝，不覆盖。

一键导出或运行 `python server.py export`：

|文件|内容|
|---|---|
|participants.csv|每人一行；模式、版本、分组、区组、容量、背景答案、题序、交换位、完成与审核状态|
|choices.csv|每人每题一行；原题号、呈现顺序、实际/原始A/B属性、价格水平、规格、选择及时间|
|choice_long.csv|每题A/B/N三行；原统计列和同义列均保留，含price_yuan、price_level、product_volume_ml、design_version|
|detail_views.csv|逐次详情查看与时间日志|
|manifest.json|模式、版本、配置哈希、规格、广告版本、导出时间及行数|

N为独立不购买备选项，opt_out=1；产品属性、price_yuan、price_level及product_volume_ml为空，不能理解为0元或1 L的真实商品。混合Logit保留participant_id面板结构；WTP使用实际元价格而非1/2/3价格等级，模型缩放换算见设计诊断报告。

## 6. QuickForm配置与正式硬锁

按用户最新指定使用默认正式接口https://quickform.cn/api/kajm9wjasx，环境变量仍为QUICKFORM_API_URL。demo永不发送；pilot须使用独立QUICKFORM_PILOT_API_URL并显式启用；本次仅更换收集地址，已有答卷和同步快照的目标不改写。

本版config/design_approval.json中的researcher_approved=false、pilot_completed=false。正式网页启动、正式参与入口及QuickForm正式发送都会校验设计版本和哈希、用户确认、预测试完成及记录引用；即使旧的DCE_ALLOW_FORMAL和QUICKFORM_FORMAL_ENABLED被设为YES，也不能绕过硬锁。本次不修改这些标志为true。

用户明确确认设计并完成预测试后，应由研究团队审核是否仍使用同一题库，再依据最终哈希记录审批；若预测试需要重优化，须另行锁定版本并重新诊断。本版本不是现在即可正式收集的批准版本。

QuickForm仅在8题和后续问卷完整提交后建一条不可变快照，Python后端POST，网络失败保留SQLite。状态pending/success/failed/uncertain保留；成功只认HTTP 200且status=success，202排队、超时及中断需核查，不无限重发。有限退避、后台重试、日志和UUID核查功能保留。UUID不是远端原生幂等保证。

新版每个实际商品的QuickForm codes和扁平字段同时包含price_yuan、price_level、product_volume_ml，文案来自实际展示快照。dce_choices_json和原始题号/位置/选择全部保存。提交结构study2-qf-v2，旧study2-qf-v1快照不改写。详情见[QuickForm说明](QuickForm_接入和查看数据.md)。

从QuickForm导出还原：

```powershell
python scripts/restore_quickform_export.py '答卷.csv' --mode pilot --design-version study2-1l-3price-v2 --output-dir 'exports\restored_v2_pilot'
```

默认版本为当前版。历史版须明确选择study2-16-v1；不同版本禁止混合还原，不补缺题、不覆盖既有分析文件。

## 7. 备份、安全与正式前置工作

原库迁移前、启动时及默认每6小时在线备份；后台可立即备份。`python server.py backup`、停止服务后 `python server.py restore --file '备份路径' --confirm` 保留。恢复前另存当前库，同库文件锁阻止服务运行中恢复。备份不自动删除，应按批准的保留政策归档并做异地保护。

data、exports、导入原件、同步快照、凭据和备份不在HTTP静态白名单内。后台PBKDF2密码哈希、HttpOnly/SameSite Cookie、CSRF、限流及权限检查保留。正式模式还需HTTPS反向代理、安全Cookie、真实研究联系/保留/撤回说明及唯一邀请码。Cookie不能保证每人仅参加一次。

config/study_config.json保留联系方式、数据保留、撤回及知情同意版本配置；当前ready_for_formal仍为false。广告数据来源及声称核查仍需完成，见广告素材使用前检查.md。未开发的绿色消费价值观量表及单独燕麦饮经验题不生成答案；问卷扩展需研究者实际开发后注册。
